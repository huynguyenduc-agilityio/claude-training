# EXP-108: Cached input tokens above input tokens give a negative cost

- **Type:** Bug
- **Priority:** High
- **Reporter:** QA (Day 6 test coverage audit)

## Description

Cached input tokens are part of the input tokens, so `cachedInputTokens` can never be larger than
`inputTokens`. `POST /api/usage` still accepts such a record, and its cost comes out negative. The
negative amount lowers the month total, the model and project breakdowns and the budget
percentage, so the numbers we copy into the monthly cost report are wrong.

Steps:

1. Send:
   ```json
   {
     "timestamp": "2026-10-15T03:00:00Z",
     "model": "orion-large",
     "project": "support-bot",
     "inputTokens": 100,
     "outputTokens": 0,
     "cachedInputTokens": 1000000
   }
   ```
2. The API answers `201 Created`.
3. The dashboard for 2026-10 shows a total cost of `-$4.50`.

## Acceptance criteria

- A record with `cachedInputTokens` greater than `inputTokens` is rejected with `400` and a message
  naming `cachedInputTokens`; nothing is saved.
- `cachedInputTokens` equal to `inputTokens` is accepted and costs only the cached rate.
- Records without `cachedInputTokens` are still accepted.

## Repro (filled in by the developer)

Reproduced on `main` at `4ab78dc` with an in-memory database and the real app: `POST` answers
`201`, `GET /api/summary?month=2026-10` answers `200` with `totalCost: -4.5`.

- Cost: `uncached = 100 - 1,000,000 = -999,900` tokens at $5 per million gives `-4.9995`, plus
  1,000,000 cached tokens at $0.50 per million gives `0.5`: `-4.4995`, shown as `-$4.50`.
- Cause: validation checks `cachedInputTokens` only for integer and non-negative
  (`usage.validation.ts:43-47`); `calculateCost` computes `inputTokens - cached` (`cost.ts:11`).
- Found by the cloud coverage audit (`docs/lessons/day-06-flagship-parallel/cloud-coverage-audit.md`, H3).
