# EXP-106: A token count above the safe integer range breaks every API call

- **Type:** Bug
- **Priority:** High
- **Reporter:** QA (Day 6 test coverage audit)

## Description

`POST /api/usage` accepts a token count that is an integer but larger than
`Number.MAX_SAFE_INTEGER` (9,007,199,254,740,991). The record is saved, and from then on every
request that reads the usage records fails with `500`: the dashboard is down for every month,
and no new record can be added, until someone deletes the row from the database.

Steps:

1. Send:
   ```json
   {
     "timestamp": "2026-10-15T03:00:00Z",
     "model": "orion-large",
     "project": "support-bot",
     "inputTokens": 9007199254740994,
     "outputTokens": 1
   }
   ```
2. The API answers `201 Created`.
3. Open the dashboard for any month, or post another valid record: both fail with `500`.

## Acceptance criteria

- `inputTokens`, `outputTokens` and `cachedInputTokens` above `Number.MAX_SAFE_INTEGER` are
  rejected with `400` and a message naming the field; nothing is saved.
- Valid records, including large counts up to `Number.MAX_SAFE_INTEGER`, are still accepted and
  read back unchanged.

## Repro (filled in by the developer)

Reproduced on `main` at `4ab78dc` with an in-memory database and the real app:

| Request | Status |
|---|---|
| `POST /api/usage` with `inputTokens: 9007199254740994` | 201 |
| `GET /api/usage?month=2026-10` | 500 |
| `GET /api/summary?month=2026-10` | 500 |
| `POST /api/usage` with a valid record | 500 |

- Error: `RangeError: Value is too large to be represented as a JavaScript number: 9007199254740994`,
  thrown when the records are read back (`listAll()`, `usage.repository.ts:50`).
- Cause: `requireInteger` (`usage.validation.ts:15-19`) uses `Number.isInteger`, which is true for
  unsafe integers. Since EXP-102 the budget alert also reads all records on every `POST`, so writes
  fail as well as reads.
- Found by the cloud coverage audit (`docs/lessons/day-06-flagship-parallel/cloud-coverage-audit.md`, H1).
