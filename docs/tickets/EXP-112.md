# EXP-112: Store project budgets and report each project's budget status

- **Type:** Feature
- **Priority:** Medium
- **Reporter:** Client (capstone, lead role)
- **Spec:** [project-budgets/spec.md](../capstone/project-budgets/spec.md), requirements R1 to R7
- **Depends on:** nothing. Can be built in parallel with EXP-113 and EXP-114 against the API in the spec.

## Description

As the budget owner, I want each project to have its own monthly budget and to see how much of it
is spent this month, so that I know early which project is about to go over.

Today the app has one company-wide budget, `MONTHLY_BUDGET_USD`. This ticket adds a budget per
project, kept in the app's database, and an API that lists every project with its budget status for
the current month. The company-wide budget does not change.

## Acceptance criteria

Amounts are USD. "This month" is the current month in the configured time zone, as for the
company-wide budget. "Spent" is the project's cost this month, computed as `byProject` in
`GET /api/summary` computes it: priced records only, rounded to cents.

```gherkin
Feature: Project budgets API

  Background:
    Given usage records exist for the projects "support-bot", "code-review" and "docs-search"

  Scenario: 1. List every project that has usage records
    When I call GET /api/project-budgets
    Then the response is 200
    And it lists each project that has a usage record in any month once, here the three projects
    And the list is sorted by project name in code-point order, so uppercase comes before lowercase
    And it states the current month as "YYYY-MM"

  Scenario: 2. A project without a budget
    Given "docs-search" has no budget
    When I call GET /api/project-budgets
    Then "docs-search" has budget null, ratio null, percent null and level "none"
    And its spent amount is its cost this month

  Scenario Outline: 3. Level from the share of the budget spent
    Given "code-review" has a budget of 10.00
    And "code-review" has spent <spent> this month
    When I call GET /api/project-budgets
    Then "code-review" has percent <percent> and level "<level>"
    And its ratio is spent divided by budget, not rounded
    Examples:
      | spent | percent | level    |
      | 0     | 0       | ok       |
      | 7.99  | 79      | ok       |
      | 8.00  | 80      | warning  |
      | 9.99  | 99      | warning  |
      | 10.00 | 100     | exceeded |
      | 12.50 | 125     | exceeded |

  Scenario: 4. Set a budget
    When I call PUT /api/project-budgets/code-review with {"budgetUsd": 12.5}
    Then the response is 200 with the project's entry, budget 12.5
    And GET /api/project-budgets shows budget 12.5 for "code-review"

  Scenario: 5. Change a budget
    Given "code-review" has a budget of 10.00
    When I call PUT /api/project-budgets/code-review with {"budgetUsd": 20}
    Then GET /api/project-budgets shows budget 20 for "code-review"

  Scenario: 6. Remove a budget
    Given "code-review" has a budget of 10.00
    When I call DELETE /api/project-budgets/code-review
    Then the response is 204
    And "code-review" has budget null, ratio null and level "none"

  Scenario: 7. Remove a budget that is not set
    Given "docs-search" has no budget
    When I call DELETE /api/project-budgets/docs-search
    Then the response is 204

  Scenario Outline: 8. Reject an invalid amount
    When I call PUT /api/project-budgets/code-review with <body>
    Then the response is 400 with error "<error>"
    And the budget of "code-review" is unchanged
    Examples:
      | body                    | error                                   |
      | {"budgetUsd": 0}        | budgetUsd must be greater than 0        |
      | {"budgetUsd": -5}       | budgetUsd must be greater than 0        |
      | {"budgetUsd": 10.005}   | budgetUsd must have at most 2 decimals  |
      | {"budgetUsd": 1000000.01} | budgetUsd must be at most 1000000     |
      | {"budgetUsd": "10"}     | budgetUsd must be a number              |
      | {"budgetUsd": null}     | budgetUsd must be a number              |
      | {}                      | budgetUsd must be a number              |

  Scenario: 9. Reject a project with no usage records
    When I call PUT /api/project-budgets/new-team with {"budgetUsd": 10}
    Then the response is 404 with error "project not found"
    And DELETE /api/project-budgets/new-team also answers 404 with error "project not found"

  Scenario: 10. Budgets survive a restart
    Given "code-review" has a budget of 10.00
    When the API restarts with the same database file
    Then GET /api/project-budgets still shows budget 10 for "code-review"
```

More rules:

- `percent` and `level` are computed in whole cents, so float error cannot move a boundary:
  with `s` the spent cents and `b` the budget cents, `percent` is `floor(100 × s / b)` in integer
  arithmetic, `warning` when `100 × s ≥ 80 × b`, `exceeded` when `s ≥ b`. For example $2.40 of $3.00
  is 80 and `warning`; $2.90 of $10.00 is 29. `ratio` is `spent / budget` for information only. The
  page never computes `percent` or `level`.
- A request is checked in this order: the project first (404), then the body (400). An unknown
  project with an invalid body answers 404.
- The body checks run in this order, and the first that fails gives the error:
  1. `budgetUsd` is a finite number. A boolean, string, array, object, `null`, a missing field, a
     body that is `[]`, a request with no body, and `1e999` (parsed as Infinity) fail with
     `budgetUsd must be a number`.
  2. Rounded to cents, it is at least 1 cent (`Math.round(budgetUsd × 100) ≥ 1`), else
     `budgetUsd must be greater than 0`. So 0, -5 and 1e-12 fail here.
  3. At most 1000000, else `budgetUsd must be at most 1000000`.
  4. At most 2 decimals: `budgetUsd × 100` is within `max(1e-9, 4 × Number.EPSILON × budgetUsd × 100)`
     of a whole number, else `budgetUsd must have at most 2 decimals`. The tolerance grows with the
     amount because above about 131072 the float error in `budgetUsd × 100` exceeds a fixed `1e-9`
     and would reject valid amounts such as 131072.02. Every amount with at most 2 decimals from 0.01
     to 1000000 passes; 10.005 and 999999.995 fail. (Changed on 2026-11-13, decided by the client.)
- A budget that passes the checks is stored and returned rounded to cents, so `10.000000000001`
  becomes `10`.
- `GET /api/project-budgets` ignores any query parameter, including `month`. With no usage records
  it answers 200 with `projects` empty.
- Fields other than `budgetUsd` are ignored. A body that `express.json()` rejects before the route
  answers 500, as every endpoint does today; this ticket does not change it. That covers invalid JSON
  and, because the parser is strict, the bodies `null` and a bare number such as `5`.
- A project whose records are all in other months, or all unpriced, has `spent` 0. With a budget its
  level is `ok` and `percent` 0; without one, `none`.
- A malformed or empty `:project`, or an encoded `/` (`%2F`), needs no special handling. Any 4xx or
  5xx answer is accepted.
- Tests can insert chosen records into the in-memory database, or test the status function on its
  own, to reach exact amounts such as 7.99. Real token prices are not needed. Scenario 10 uses a
  database file in the system's temporary folder, deleted after the test, never `data/usage.db`.
- A project name in the URL is percent-encoded. Names with spaces, commas, quotes or other
  characters work, for example `search, v2`.
- The project name must match a record's `project` exactly, including case.
- A budget does not belong to a month. It applies to the current month until it is changed or
  removed.
- `GET /api/summary`, the company-wide budget, its banner and its alert do not change.
- Setting or removing a budget sends no log line and no webhook.
- `pnpm seed` leaves no project budgets, so the sample data stays the same on every machine.

## Scope

- Storing, changing and removing one budget per project.
- `GET /api/project-budgets`, `PUT` and `DELETE /api/project-budgets/:project`, as in the spec.
- Server tests for every criterion above.

## Non-scope

- The dashboard (EXP-113, EXP-114).
- Past months, budget history, and budgets that differ per month.
- Notifications for projects: log lines, webhooks, email.
- Rejecting usage records when a project is over budget.
- Warning levels per project. Levels stay at 80% and 100%.
- Teams that own several projects, sign-in and permissions.
- Currencies other than USD.
