# EXP-109: One usage row without a price breaks every read of its month

- **Type:** Bug
- **Priority:** High
- **Reporter:** Claude review of EXP-107 (PR #4, points 1 and 2)

## Description

A usage row that cannot be priced makes every read of its month answer `500` until someone deletes
the row by hand. Such a row exists when its model was removed from `pricing.json`, when it was saved
with a name like `constructor` before EXP-107, or when its timestamp is older than the model's first
price period.

Steps:

1. Have a saved row with a model that is not in `pricing.json`, in the current month.
2. Open the dashboard for that month: `GET /api/summary` and `GET /api/usage` answer `500`, so the
   whole page fails. The CSV export fails too.
3. Post a valid record, or an invalid one: both answer `500`, and nothing is saved.

## Acceptance criteria

- `GET /api/usage`, `GET /api/usage/export.csv` and `GET /api/summary` answer `200` for a month with
  a row that has no price: an unknown model, a name inherited from `Object.prototype`, or a
  timestamp before the model's first price period.
- `GET /api/usage`: the row stays in `items` with `cost: null`, and `totalCost` leaves it out.
- `GET /api/summary`: `totalCost` and `budget.spent` leave the row out, `recordCount` counts it,
  `byModel` and `byProject` hold only priced rows, and `unpricedCount` is the number of such rows
  (`0` when there are none).
- CSV: the row is kept with an empty `Cost (USD)` cell, and the cost column still sums to
  `totalCost`.
- `POST /api/usage` in a month with such a row answers as usual: `201` for a valid record, `400` for
  an invalid one. The budget alert counts the row as $0.
- A new record with no price at its timestamp is saved and answers `201`, without a budget
  notification.
- The dashboard shows a warning banner with the number of such rows for any month that has some,
  and `—` in the row's cost cell.
- `getPrice` still throws `Unknown model: <name>`, and the tests of EXP-107 pass unchanged.
- No row is migrated or deleted.

## Repro (filled in by the developer)

Reproduced on `main` at `2e9fc71` with an in-memory database, the real app, and rows inserted
directly in the repository:

| Request, in a month with such a row | Expected | Actual |
|---|---|---|
| `GET /api/usage` | 200 | 500 |
| `GET /api/usage/export.csv` | 200 | 500 |
| `GET /api/summary` | 200 | 500 |
| `POST /api/usage`, valid record, row in the current month | 201 | 500, nothing saved |
| `POST /api/usage`, invalid record, row in the current month | 400 | 500 |
| `POST /api/usage`, current month, model with no price at that time | 201 | 500, record saved |

- Errors in the log: `Unknown model: constructor`, `Unknown model: removed-model` and
  `No price for orion-mini at 2026-09-10T08:00:00.000Z`, from `getPrice` (`pricing.ts:41`, `:44`).
- Cause: `getPrice` throws inside the loops in `usage.query.ts:34` and `summary.ts:47`, and for the
  new record in `budget.alert.ts:79`. `createBudgetAlert` also summarizes the current month before
  it parses the body, so a `POST` fails before validation runs.
- Found by Claude's review of EXP-107, points 1 and 2
  (`docs/lessons/day-09-hooks-automation/exercise-claude-review.md`).
