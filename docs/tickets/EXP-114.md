# EXP-114: Set and remove project budgets from the dashboard

- **Type:** Feature
- **Priority:** Medium
- **Reporter:** Client (capstone, lead role)
- **Spec:** [project-budgets/spec.md](../capstone/project-budgets/spec.md), requirements R11 to R14
- **Depends on:** the `/api/project-budgets` contract in the spec (EXP-112). Do after EXP-113, since
  both change `app/web/src/App.tsx`.

## Description

As the budget owner, I want to set, change and remove each project's budget on the dashboard, so
that I do not need a developer or a server restart to change a budget.

The app has no sign-in, so anyone who opens the dashboard can change a budget. The client accepted
this.

## Acceptance criteria

```gherkin
Feature: Project budgets form

  Scenario: 1. One row per project
    Given usage records exist for "code-review", "docs-search" and "support-bot"
    And "code-review" has a budget of $10.00
    When I open the dashboard
    Then a "Project budgets" section lists the three projects in the API's order
    And each row shows the project, its spending this month and its budget
    And "code-review" shows 10 in its budget field and "$10.00" next to it
    And "docs-search" and "support-bot" show an empty budget field and "No budget"

  Scenario: 2. Set a budget
    Given "docs-search" has no budget
    When I type 15 in its budget field and press "Save"
    Then the row shows "Saved"
    And the budget field shows 15 and "$15.00" shows next to it
    And the project banners reload

  Scenario: 3. Change a budget
    Given "code-review" has a budget of $10.00
    When I replace it with 7.5 and press "Save"
    Then the row shows "Saved", the budget field shows 7.5 and "$7.50" shows next to it

  Scenario: 4. Remove a budget
    Given "code-review" has a budget of $10.00
    When I press "Remove" on its row
    Then the row shows "No budget" and an empty budget field, and no other message
    And the project banners reload

  Scenario: 5. Remove is only offered when a budget is set
    Given "docs-search" has no budget
    Then its row has no "Remove" button

  Scenario Outline: 6. The API rejects an amount
    When I type "<typed>" in the "code-review" budget field and press "Save"
    Then the row shows the API's error "<error>"
    And the field still shows "<typed>"
    And nothing else on the page changes
    Examples:
      | typed  | error                                  |
      | 0      | budgetUsd must be greater than 0       |
      | -5     | budgetUsd must be greater than 0       |
      | 10.005 | budgetUsd must have at most 2 decimals |
      |        | budgetUsd must be a number             |

  Scenario: 7. The request fails without a response
    Given the API cannot be reached
    When I press "Save" on a row
    Then the row shows "Could not save: " followed by the error text
    And the field still shows what I typed

  Scenario: 8. A month other than the current one
    Given the current month is 2026-11
    When I choose a past month on the dashboard
    Then the section still shows this month's spending and the budgets
    And it reads "Spending shown for 2026-11."

  Scenario: 9. Remove fails
    Given "code-review" has a budget of $10.00
    When I press "Remove" and the API cannot be reached
    Then the row shows "Could not remove: " followed by the error text
    And the row still shows the budget

  Scenario: 10. No projects yet
    Given there are no usage records
    When I open the dashboard
    Then the section reads "No projects have usage records yet."

  Scenario: 11. The budgets cannot be loaded
    Given GET /api/project-budgets fails
    When I open the dashboard
    Then the section reads "Project budgets are unavailable."
```

More rules:

- The section sits below the Add record form and above the banners and totals. Like the Add record
  form, it stays on the page while the month's data reloads, so a row's message and typed text are
  kept.
- The budget field is a number field. It shows the budget as the API returns it, for example `15` or
  `7.5`. The amount in the money format, for example `$15.00`, shows next to it.
- A row's message ("Saved" or an error) stays until that row's field is edited or its Save or Remove
  is pressed again.
- After Save or Remove succeeds, only `GET /api/project-budgets` reloads (EXP-113).
- While the budgets load for the first time, the section reads "Loading project budgets…".
- The month in "Spending shown for …" is the `month` from `GET /api/project-budgets`. The sentence
  shows only when the month picked on the dashboard differs from that `month` and the list is not
  empty.
- When the budgets reload, rows keep what they showed until the response arrives. After the
  response, every row other than the one just saved or removed keeps its typed, unsaved text and its
  message. The row just saved shows the budget as the API returns it, for example `15` after typing
  `15.0`. A failed reload is handled like a failed first load.
- Text the browser cannot read as a number, such as "abc", leaves the number field empty, so it is
  sent as `null` and the API answers `budgetUsd must be a number`.
- While a row's request is pending, its Save and Remove buttons are disabled. Save sends a request
  even when the value did not change.
- Messages: when the API answers 4xx, the row shows its `error` text alone, or, when the response
  has no `error`, the app's existing fallback text alone, for example `Request failed: 404`. When there is no
  response, or the API answers 5xx, the row shows "Could not save: " or "Could not remove: "
  followed by the error text.
- The form has no rules of its own; the API decides what is valid, as in EXP-111. An empty field
  is sent as `null`, not `0`.
- Each row saves on its own. A message on one row does not change the others.
- Only projects that already have usage records are listed. There is no field for a new name.

## Scope

- The "Project budgets" section: list, set, change, remove.
- Reloading the banners from EXP-113 after a change.

## Non-scope

- Budgets for projects with no usage records.
- Sign-in or restricting who can change budgets.
- Budget history and undo.
- Any change to the API (EXP-112) or to the company-wide budget.
