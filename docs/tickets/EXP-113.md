# EXP-113: Show a banner for each project that is near or over its budget

- **Type:** Feature
- **Priority:** Medium
- **Reporter:** Client (capstone, lead role)
- **Spec:** [project-budgets/spec.md](../capstone/project-budgets/spec.md), requirements R8 to R10
- **Depends on:** the `GET /api/project-budgets` response in the spec. Build against that contract in
  parallel with EXP-112; check end to end once EXP-112 is merged. Do before EXP-114, since both
  change `app/web/src/App.tsx`.

## Description

As the budget owner, I want the dashboard to tell me which project is near or over its budget this
month, so that I can act before the end of the month.

The dashboard already shows one banner for the company-wide budget. This ticket adds one banner per
project right below it: under the Add record form and the Project budgets section (EXP-114), above
the unpriced-records banner. They show only
for the current month, like today's banner, and stay for as long as the project is at that level.
They cannot be dismissed.

## Acceptance criteria

```gherkin
Feature: Project budget banners

  Background:
    Given the dashboard shows the current month

  Scenario: 1. A project at 80% or more
    Given "code-review" has a budget of $10.00 and has spent $8.12 this month
    When I open the dashboard
    Then I see a warning banner that reads
      "Budget warning for code-review: $8.12 of $10.00 spent this month (81%)."

  Scenario: 2. A project at 100% or more
    Given "code-review" has a budget of $10.00 and has spent $12.50 this month
    When I open the dashboard
    Then I see an exceeded banner that reads
      "Budget exceeded for code-review: $12.50 of $10.00 spent this month (125%)."

  Scenario: 3. Projects with no banner
    Given "support-bot" is below 80% of its budget
    And "docs-search" has no budget
    When I open the dashboard
    Then I see no banner for "support-bot" or "docs-search"

  Scenario: 4. Several projects over a level
    Given "a" is at 85%, "b" is at 130% and "c" is at 110% of their budgets
    When I open the dashboard
    Then the project banners appear in the order "b", "c", "a"

  Scenario: 5. Next to the company-wide banner
    Given the company-wide budget is at 90%
    And "code-review" is over its budget
    When I open the dashboard
    Then the company-wide banner appears first, unchanged
    And the "code-review" banner appears below it

  Scenario: 6. A past month
    Given "code-review" is over its budget this month
    When I choose a past month on the dashboard
    Then I see no project banners

  Scenario: 7. The banners follow new usage
    Given "code-review" has a budget of $10.00 and has spent $7.90 this month
    When I add a usage record for "code-review" with the Add record form that brings it to 80% or more
    Then the "code-review" warning banner appears without reloading the page

  Scenario: 8. The budgets cannot be loaded
    Given the dashboard shows the current month
    And GET /api/project-budgets fails
    When I open the dashboard
    Then I see one line "Could not load project budgets: " followed by the error text, where the
      project banners would be
    And no project banner shows
    And the rest of the dashboard still shows
```

More rules:

- Amounts use the dashboard's existing money format. The percentage is the API's `percent`. The page
  does not compute it.
- Warning banners look like today's warning banner, exceeded banners like today's exceeded banner.
- Order: exceeded before warning; within each, the higher share first, compared in whole cents
  (`s1 × b2` against `s2 × b1`); equal shares by project name in code-point order.
- The page shows banners when `summary.isCurrentMonth` is true, as for the company-wide banner. On a
  past month neither the banners nor the load error line show.
- `GET /api/project-budgets` is fetched on its own, outside the `Promise.all` that loads the month,
  so its failure does not stop the rest of the page. While it loads for the first time, the banner
  area shows nothing. When a usage record is added, the month's data reloads and the page shows
  "Loading…" as it does today; the banners go with the rest and come back when both loads finish.
  When only the budgets reload (after Save or Remove in EXP-114), the banners already shown stay
  until the response arrives. A failed reload is handled like a failed first load.
- The banners and the load error line show only when the month's summary has loaded and
  `summary.isCurrentMonth` is true.
- The page reads levels from the API. It does not compute them.
- When a usage record is added, the page reloads its data as it does today, and the project budgets
  with it. When a budget changes (EXP-114), only `GET /api/project-budgets` reloads.

## Scope

- The banners and their placement on the dashboard.
- Loading `GET /api/project-budgets` on its own, when the page opens and again after a usage record
  is added.

## Non-scope

- Setting or removing budgets (EXP-114).
- Any change to the company-wide banner.
- Dismissing a banner, sounds, browser notifications.
- Banners for past months.
